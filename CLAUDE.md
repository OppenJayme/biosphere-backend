# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

This is a NestJS backend (`biosphere-backend`) currently at its initial scaffold stage — the only application code is the default `AppModule`/`AppController`/`AppService` generated by `@nestjs/cli`. There is no database, no config module, and no additional feature modules wired up yet. When adding features, follow standard NestJS conventions (modules/controllers/services/DTOs) since no project-specific architecture exists to deviate from.

## Commands

```bash
npm run start:dev      # run with watch mode (primary dev loop)
npm run start:debug    # watch mode + --inspect-brk debugger
npm run build          # nest build -> dist/
npm run start:prod     # run compiled output from dist/main

npm run lint           # eslint --fix over src, apps, libs, test
npm run lint:ci        # eslint without --fix (used in CI)
npm run format         # prettier --write over src/**/*.ts and test/**/*.ts

npm run test           # jest unit tests (rootDir: src, matches *.spec.ts)
npm run test:watch     # jest --watch
npm run test:cov       # jest --coverage
npm run test:e2e       # jest -c test/jest-e2e.json (matches test/**/*.e2e-spec.ts)
npm run test:debug     # jest --runInBand with node --inspect-brk
```

Run a single unit test file: `npx jest src/app.controller.spec.ts`
Run a single e2e test file: `npx jest --config ./test/jest-e2e.json test/app.e2e-spec.ts`
Run tests matching a name: `npx jest -t "test name pattern"`

## CI

`.github/workflows/ci.yml` runs on every PR/push to `main`: `npm ci` → `lint:ci` → `test` → `build` → `test:e2e`, on Node 20. Match this sequence locally before pushing.

## Architecture notes

- Unit test specs (`*.spec.ts`) live alongside their source files under `src/`, per Jest's `rootDir: src` config in `package.json`. E2E specs (`*.e2e-spec.ts`) live under `test/` with their own Jest config (`test/jest-e2e.json`).
- `tsconfig.json` targets ES2023 with `nodenext` module resolution, decorators enabled (required for Nest DI), and `strictNullChecks` on but `noImplicitAny` off.
- ESLint (`eslint.config.mjs`) uses `typescript-eslint`'s `recommendedTypeChecked` plus Prettier integration; `no-explicit-any` is disabled, and `no-floating-promises`/`no-unsafe-argument` are downgraded to warnings.
- Prettier config: single quotes, trailing commas everywhere (`.prettierrc`).
- The app listens on `process.env.PORT`, defaulting to `3000`.
